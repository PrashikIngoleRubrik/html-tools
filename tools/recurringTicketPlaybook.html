Root cause (CPQKTLO-14260): CustomReplacementController.cls groups disposed lines onto a replacement line with key.contains(...) — a literal substring check, not a set comparison. A disposed line only groups correctly if its own Id-pair from Arroyo_Subsumed_Old_Contract_Line_Items__c appears as one contiguous, same-order chunk inside the replacement line's value. The fix is just concatenating each disposed line's own chunk, in order — never reordering the Ids within a chunk.
